# System Patterns: 氡气监测系统
*Version: 1.0*
*Created: 2024-07-07*
*Last Updated: 2024-07-07*

## Architecture Overview
氡气监测系统采用分层架构设计，基于FreeRTOS操作系统实现多任务并行处理。系统分为硬件抽象层、驱动层、通信层、业务逻辑层和应用层。使用消息总线（Message Bus）作为核心通信机制，实现各模块间的松耦合和异步通信。基于命令处理器模式处理串口通信协议，支持不同类型的命令解析和处理。

## Key Components
- **硬件抽象层(HAL)**: 封装底层硬件细节，提供统一的访问接口
- **驱动层**: 实现各种外设驱动，如USART驱动、传感器驱动等
- **通信层**: 实现串口通信协议处理，包括命令解析和响应生成
- **业务逻辑层**: 实现数据处理、报警判断、状态管理等核心业务逻辑
- **应用层**: 实现任务调度、用户交互、系统配置等高层功能
- **消息总线**: 作为系统内部通信的统一渠道，实现模块间的解耦
- **任务管理器**: 负责管理FreeRTOS任务的创建、删除和调度

## Design Patterns in Use
- **单例模式**: 用于UartProtocolProcessor、USART1Driver等全局唯一的服务类
- **命令模式**: CommandProcessorBase基类定义统一的命令处理接口，各具体命令实现不同的处理逻辑
- **观察者模式**: MessageBus实现发布-订阅模式，用于系统组件间的事件通知
- **工厂模式**: 任务工厂用于统一创建和管理系统任务
- **策略模式**: 不同的协议处理器实现不同的协议解析和处理策略
- **适配器模式**: CommInterface抽象类适配不同的通信接口实现

## Data Flow
1. 传感器采集原始数据 -> 硬件抽象层处理 -> 驱动层数据转换
2. 驱动层生成数据消息 -> 消息总线分发 -> 业务逻辑层处理
3. 外部命令通过UART接收 -> 命令解析器处理 -> 执行相应操作
4. 业务逻辑层处理结果 -> 消息总线分发 -> 驱动层发送响应
5. 状态变化触发事件 -> 消息总线通知 -> 相关组件响应处理

## Key Technical Decisions
- **使用FreeRTOS**: 提供可靠的多任务调度和资源管理，支持实时响应
- **采用C/C++混合编程**: 核心功能使用C++面向对象设计，资源受限部分使用C语言
- **双缓冲DMA接收**: 提高串口通信效率，减少CPU占用
- **消息缓冲区设计**: 使用FreeRTOS的MessageBuffer进行任务间数据传递
- **命令处理器架构**: 可扩展的命令处理框架，便于添加新命令
- **任务切片调度**: 避免单一任务长时间占用CPU，提高系统响应性

## Component Relationships
- **UartProtocolProcessor**: 继承自CommandProcessorBase，负责解析和处理串口协议命令
- **USART1Driver**: 继承自CommInterface，实现串口通信基本功能
- **MessageBus**: 系统消息总线，连接各个模块，实现消息的发布和订阅
- **任务调度器**: 管理各个任务的运行，包括串口通信任务、传感器采集任务、数据处理任务等
- **按键控制**: 处理用户输入，触发相应的系统操作
- **LED控制**: 提供系统状态指示，与状态管理模块连接
